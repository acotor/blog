最近把博客从 Gridea 迁到了 Hugo。

过程比我预想的轻松。大部分时间，我是在和 AI Agent 讨论：想要什么样的博客、文章和图片怎么迁移、主题哪里需要调整。具体的资料查找、文件处理、配置和验证，很多都由它来完成。

博客搬完之后，回头想想，这件事对我来说不只是换了一个工具。我一直想找一个合适的地方，把自己的想法和经历整理下来，分享出去。博客的形式和写作的欲望之间，我徘徊了挺久。现在，总算可以把注意力更多地放回写作本身。

## 为什么还是想写博客

社交平台很适合随手说点什么，看到有意思的东西也能马上转发、讨论。但当我想认真记录一段经历，或者把一个想法从头到尾讲清楚时，还是更喜欢博客。

一方面，长文字需要一点空间，让我把事情的背景、过程和自己的判断都写下来，而不是尽量压缩成几句话。另一方面，在简体中文互联网，许多内容都留在各个平台内部。有些平台也有不错的长文创作和发布服务，但文章未必容易被开放互联网检索到，也往往要依赖平台的规则才能被阅读和分享。

个人博客是很传统的方式，但它足够开放。一篇文章发布在自己的域名下，别人可以通过链接访问，也有机会通过搜索找到它。对我来说，它仍然是长文字创作最理想的选择之一。

我想写博客，并不只是想留一个自己的网址。更重要的是，写作能帮我整理想法，记录自己做过的事；分享出去之后，也许还能和有相似兴趣的人交流。

## 当初为什么选择 Gridea

我之前用的是 [Gridea](https://github.com/getgridea/gridea)，文章通过 GitHub Pages 发布。

当时选择它的理由很简单：想要一个主题简洁的博客，写作和发布最好有图形界面，但又不想为了个人博客去维护 WordPress 这样相对重一些的系统。Gridea 正好符合我的需求。打开客户端写文章、选择主题，然后生成静态页面并发布，很多技术细节都被放在了界面后面。

现在回头看，这仍然是个不错的选择。Gridea 让我不必先弄明白静态站点生成器和各种命令，也能拥有自己的博客。

后来 Gridea 也逐渐发展出了[提供写作和托管的云服务](https://gridea.dev/)，支持在电脑和手机上使用，还提供自定义域名等功能。它试图把写作、管理和发布放在一处，让人不必操心太多技术问题。我觉得这个方向挺好，愿意为省心付费的话，它也是一种选择。

我自己这次没有选择付费服务。一方面，我希望文章和站点配置能以文件的形式保存，换工具时更容易带走；另一方面，我已经在用 GitHub Pages，也想继续保持静态博客比较简单的架构。

## 线上博客还在，写作环境却不一定在

旧博客的文章和配置放在笔记本电脑上。只要那台电脑和 Gridea 的数据都在，写作和发布就没什么问题。但时间长了，我开始觉得这种方式不太方便：换一台电脑，或者本地源文件没有妥善保存，要恢复原来的写作环境就需要再费一番工夫。

虽然发布后的网页还在 GitHub Pages 上，但网页和写作时使用的源文件不是一回事。要继续舒服地修改文章、调整站点，还是得照顾好本地的数据和配置。

Gridea 本身支持自定义源文件目录，也可以借助云盘同步多台设备。只是对我来说，怎么保存、怎么同步、以后怎么恢复，仍然是要留心的事。我希望博客的源文件有一个更清楚的保存和管理方式，不要只依赖某一台电脑上的客户端。

于是有了这次迁移。

## AI Agent 让另一套方式变得可用

以前我也知道 Hugo 这类静态站点生成器：用 Markdown 写文章，通过主题和配置生成网页，再部署到托管平台。它的思路很符合我想要的“轻量、文件容易保存”的要求。

但知道是一回事，用起来又是另一回事。配置站点、管理 Git 仓库、处理图片路径和主题，哪怕每件事单独看都不算特别难，放在一起也需要不少时间。对于想写博客的我来说，Gridea 的图形界面当时更有吸引力。

现在有了 AI Agent，情况变了。

这次迁移时，我把原来的 Gridea 数据交给 Samantha（我部署在一台 7×24 小时运行的服务器里的 [Hermes Agent](https://hermes-agent.nousresearch.com/)），和她讨论需求，再由她协助检查文章、处理迁移、配置 Hugo 和 GitHub Actions。主题也不是选好之后就完全满意：页面的字体、间距、页脚和图标，我会根据看到的效果继续提意见，她再帮我调整和验证。

我并没有亲手完成每一步，但也不是只说一句“帮我迁移”就不管了。选什么方案、保留什么、页面呈现成什么样，这些决定还是由我来做。遇到看不明白的地方，也可以随时让她解释。

整个过程对我来说很自然，但我知道背后并不简单。技术一直在变化，即使是有经验的人，也常常需要查阅最新资料、核对配置、解决问题。AI Agent 并没有让这些工作消失，而是帮我承担了其中很大一部分。

现在这套博客大致是这样的：

```text
Markdown 文章、图片、主题和配置
                ↓
          GitHub 源文件仓库
                ↓
      GitHub Actions 运行 Hugo 构建
                ↓
        GitHub Pages 发布网站
```

源文件有了共同的保存和同步位置。我的笔记本和 Agent 所在的主机都可以保留一份副本；以后我可以自己用编辑器写，也可以把想法交给 Agent 协助整理、修改。发布前再由我确认。

这套方式并不意味着以后都要让 AI 代笔。我仍然喜欢自己琢磨怎么表达，也希望保留从头写一篇文章的可能。Agent 可以帮我处理仓库、主题和发布这些事情，也可以在我需要时参与写作；用到什么程度，由我自己决定。

当然，文件放在 GitHub 上也不代表从此不用考虑备份。多设备编辑时要注意同步，公开仓库里也不能随意放私人草稿和密钥。只是相比过去，我更清楚源文件在哪里，以及该怎样继续管理它们。

## 搬家之后，还是要写

这次迁移让我有个很直接的感受：工具真正变得简单易用，不一定是因为它背后的技术变简单了，也可能是因为有人帮忙处理了那些繁杂的部分。

以前我需要花更多精力去弄清楚怎么配置、怎么操作；现在可以把更多时间留给“我想做什么、想写什么，以及怎么把它们做好、写清楚”。对我来说，这种变化比换了一个主题或者生成器更有意思。

不过，博客搬完家，事情也并没有结束。

寻找理想的博客形态这件事，我已经花了不少时间。现在有了一个还算满意的结果，接下来博客会变成什么样，还是取决于我有没有继续写下去。想分享的东西并不会因为换了工具就自动变成文章。

希望这次能给自己一个更容易创作的起点。把一些想法和经历慢慢整理下来，写出来，分享出去。如果有人恰好读到，也愿意交流，那就再好不过了。
